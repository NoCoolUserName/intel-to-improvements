# Intel to Improvements — implementation specification

Precedence: replacement third prompt > Customer Profile addendum > original build prompt. Local-only, single-operator Python/FastAPI/Pydantic/SQLite service and React/TypeScript/Vite workbench. No remote hosting, automatic emulation, autonomous agents, mailbox polling, or credential-dependent demo.

## Context and identity
Customer is the top-level context, with editable sector taxonomy and versioned child environments. Every job freezes customer/environment, policy, source revision, and destination. Keep source occurrence, immutable content revision, logical document, extraction revision, and assessment distinct. Exact duplicates share content within authorized scope while retaining occurrences; changed content creates revisions; near-duplicates are candidates only. Source ingestion and customer receipt are separate immutable clocks. Private content cannot cross customer boundaries via a content hash.

## Vertical slices, in order
A. Versioned evidence schemas, customer editing, immutable snapshots, safe selected URL/local path/upload ingestion, limited attributed real case, standards-valid STIX and native PyMISP exports.
B. Deterministic relevance policy, evidence-linked ordered hunts and safe human-led validation plans, pinned public Sigma/ATT&CK/Atomic catalogs, independent coverage dimensions and append-only validation/improvement history.
C. Chat-connected Gmail assisted handoff only: prepare frozen request, copy instructions, validate/preview/process bounded versioned JSON through the same services. No app Gmail authentication or direct network adapter. Support text/Markdown/HTML/CSV/STIX/MISP/EML/text PDF and explicitly flag unparsed images/attachments.
D. Regression/evaluation reports, polished local UI, browser checks, documented five-minute demonstration, reproducible packages and initial implementation commit if permitted.

## Evidence and processing
Canonical schemas cover source, spans, claims, observables, behaviors, relationships, customers/environments, hunts, emulation, candidates, coverage, improvements, tests and attachments. Every assertion has supporting span IDs; proposed actions also name assumptions. Source reports, inferences, proposals and unsupported/conflicting claims stay distinct. Negation and attribution uncertainty are retained. Confidence separates extraction certainty from source reliability. Deterministic code controls IDs, validation, storage, exports and transitions.
Replay is explicitly prerecorded and content-hash selected; authored deterministic analysis is explicitly bounded and never described as live AI. Real configurable OpenAI structured extraction uses selected spans, no tools, limits, timeout/retry, cache/checkpoints, failure persistence, no silent fallback. No credentials required for replay. General live extraction remains NOT VERIFIED without an actual successful request.

## Relevance
Versioned deterministic policy records sector targeting separately from mentions, technology/behavior fit, intelligence requirements, confidence and recency. Supported technology match can yield High despite sector mismatch. Missing sector is Unknown, not Low. Recommended includes High/Medium/Unknown; Low remains inspectable. Overrides need reasons. Partial sources remain visible and warnings flow to artifacts.

## Exports and decisions
STIX 2.1 library and validator; PyMISP native event; stable scoped identities; unpublished org-only MISP; no inferred TLP or observation dates. Preserve import identities, losses and review warnings. Explicit optional MISP action previews issues, upserts by customer/destination/document identity, checks remote conflicts and retrieves readback. Converter and live import are distinct checks.
Sigma discovery reports subset size/revision and cited versus independent retrieval. pySigma Splunk raw-field conversion is distinct from runtime testing. Restricted synthetic matcher rejects unsupported constructs and missing fields are inconclusive. Atomic metadata is pinned and verified; dangerous stages receive safe approximations with limits.
Coverage records telemetry, detection readiness, deployment, synthetic/lab/live detection, prevention and SOC response independently. A passing fixture never yields live verification. Version changes stale prior evidence. Test records require scope, versions, procedure, actual/expected, execution and recording time, evidence, and method. Timings never substitute zero for pending and never combine synthetic with operational evidence.

## Security and bounded operation
Loopback default; same-origin and host checks; explicitly selected regular local files only, no directory scan; size/type/path protections; public HTTP(S) fetching with IP/redirect validation and response/time limits, never IOC fetching. Render text safely. No report command execution. Raw articles remain ignored runtime data; bundle only minimal excerpts/derived data and independently authored fixtures, with separate third-party notices.
Jobs persist checkpoints and rejected output; deduplicate concurrent submissions; cancellation is cooperative between stages/model chunks, restart returns interrupted jobs to resumable state.

## Gmail contract
Portable versioned JSON references a stored request and exact frozen customer/environment context, supports split batches, account/message identity when returned, body representation, supported serials with content segment, provenance, gaps and nullable counts. Import never trusts email instructions, never follows links/file references, never fabricates MIME/headers/attachments. Snippets/truncation remain partial. User confirms existing plugin works; selected retrieval, handoff import, live model and MISP are separate readiness results.

## Completion evidence
Run tests and held-out evaluation with actual counts, false assertions and limits. Document exact commands and versions. Exercise unseen source through live model only if configured; otherwise record unavailable. Live Gmail requires selected operator scope; live MISP requires configured instance. Ship run manifest, actual evaluation JSON/HTML, README/ARCHITECTURE/VALIDATION/THIRD_PARTY_NOTICES/DEMO and checkpoint. Extensions are documented only.
